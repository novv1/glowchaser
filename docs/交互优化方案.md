## 一、现状与诊断

技术栈：FastAPI + 原生 JS，**零构建步骤**、无 npm 依赖，ECharts/Leaflet 已本地化到
`app/static/vendor/`。样式全部走 CSS 变量（`:root` / `html[data-theme="dark"]`）。
当前共有 25 个卡片容器、5 个 Tab 面板 + 独立的「悬日月」模式。

先确认健康度：`tests/unit` 130 项全绿，代码本身没坏。**线上实例已经废了**——
`app.workbuddy.link` 那个地址仍能打开，但返回「网络获取失败，正在显示最近一次成功报告」，
拿到的是上一次缓存、概率显示 `--%`。它已无法取数，因此优化重点应落在本地体验。

实测暴露的问题（均为截图/代码可验证，不是主观感受）：

1. **加载态只有一行灰字。** `#loading` 是一行文字（`index.html:45`），后端多模式评分要
   十几秒，这期间整页空白，用户不知道是在跑还是卡死，也没有取消入口。
2. **错误态混乱。** 实测截图里 `数据获取失败: Failed to fetch` 这行字会**与渲染完整的
   报告同时存在**，因为它和报告渲染是两条互不清理的路径（`app.js:2086` 只改文本、
   `:2090` 只在成功分支隐藏）。同时还有第三种状态（缓存回退 + `#cacheBanner`）三套并存。
3. **无信息层次。** 概览页 9 张卡一次性全部出现，概率、最佳时段、效果预览这些
   「决策信息」与「专业性细节」同等权重堆在一条长滚动里。
4. **动效几乎为零。** 只有切 Tab 的 `paneIn`（`style.css:143`）和悬停过渡；
   进度条是一次性设宽、概率是直接写文本，无入场、无计数、无骨架。
5. **无 URL 状态。** Tab 记忆在 localStorage（`app.js:38`），刷新可以恢复，但
   **不可后退、不可分享、不可深链**到某个城市/日期/模式。
6. **顶栏语义模糊。** 城市、日期、朝晚霞、模式**全部是即改即查**（`app.js:99-105`、
   `:242-247`、`:256-262`），所以「查询」按钮（`index.html:30`）实际是冗余的，
   用户无法从界面判断什么时候非点它不可。
7. **移动端拥挤。** 860px 单列，顶部一条 topbar + 一条 tabnav 常驻粘滞，
   小屏上首屏几乎全被导航吃掉（`.tabnav { top: 96px }` 已经是打补丁的痕迹）。
8. **无动效降级。** 没有 `prefers-reduced-motion` 处理。

## 二、三个方案

### 方案 A · 轻装打磨（只改样式层）

改动集中在 `style.css` + 少量 JS 触发器，**不动 HTML 结构、不动查询流程**。

- 主题包体系（四选一，见下节）+ 令牌补齐（阴影/圆角/字重/间距统一）
- 骨架屏（shimmer）替代那行灰字
- 卡片入场、进度条生长、概率数字滚动、按钮反馈
- `prefers-reduced-motion` 降级

收益明确、风险最低、一次改完即可看到质变。但**问题 1/2/5/6/7 都不解决**，
本质是"换皮"。工作量：小。

### 方案 B · 交互流程重构（推荐）

A 的全部内容，再加：

- **加载态**：骨架屏 + 分阶段进度文案（复用后端真实阶段：多模式取数 → 光路采样 →
  评分 → 地图网格），并给「取消/重试」按钮
- **错误/空态**：统一为独立状态卡片，替换裸文本；缓存回退与实时失败互斥呈现
  （修掉问题 2）；无对准窗口等空态给出下一步动作
- **首屏优先渐进呈现**：hero + 最佳时段 + 霞光模拟先出现，其余卡片用
  IntersectionObserver 滚动到才淡入（也是性能优化）
- **URL hash 路由**：`#/glow/overview`、`#/glow/maps`、`#/align`，
  携带城市/日期/模式，支持刷新、后退、分享深链（问题 5/6）
- **顶栏精简**：把冗余的「查询」降级为图标按钮（或改为「刷新」语义 + 最后更新时间），
  次要控件收进「更多」；主题切换由圆形图标改为下拉（主题包 + 深浅）
- **移动端底部导航**：小屏改为底部标签栏，顶栏只留品牌 + 城市 + 刷新（问题 7）
- **键盘可达性**：Tab 顺序、焦点环、`aria-*` 补齐（现有搜索框已有良好先例可循）

工作量：中。改动 `index.html` + `app.js` + `style.css` 三件套，但评分/取数逻辑不动。

### 方案 C · 整体重做

B 的全部内容，再加重排信息架构：

- 概览压缩为「决策卡」（今晚拍不拍 + 去哪 + 几点），其余细节折叠进「专业详情」
- Hero 改为"天象仪表盘"：概率环 + 事件时间轴 + 天空缩略图
- ECharts 统一主题化（现在各图配置里散落硬编码色，`baseMapOption()` 就是浅色写死）
- 分享图（`share.js` 330 行）按新视觉重设计

效果上限最高，但**回归面最广**（图表 ×10 实例、天空渲染 `sky.js`/`sky_preview.js`、
分享图、快照测试都要跟着改），且信息架构变动会改掉你已习惯的布局。工作量：大，风险：高。

## 四、动效分档

**克制**：仅骨架屏 + 进度条生长 + 按钮反馈。无入场动画，最省心。

**标准（推荐）**：

1. 顶栏滚动时收窄 + 毛玻璃（现在是实心色条）
2. Tab 滑动指示器（现在每个按钮各自变色，改为一个滑动胶囊）
3. 卡片入场：滚动到视口 fade-up，同屏内错峰 60ms
4. 骨架屏 shimmer 扫光
5. 概率数字 0 → N% 滚动（rAF + easeOutCubic）
6. Hero 概率环描边动画（SVG）
7. 维度条/对比条进入视口时从 0 生长（现在是一次性赋值）
8. 主按钮点击涟漪 + 按下缩放
9. 图表容器切 Tab 时 scale 0.98 → 1 淡入
10. 全部尊重 `prefers-reduced-motion: reduce` → 降级为瞬时

**沉浸**：标准档 + 页面背景随太阳高度角的天光渐变、天空画布逐帧绘制入场、滚动视差。
观感最强，但要盯帧率，低端机可能掉帧。

## 五、验收

- `tests/unit` 130 项保持全绿（本次不动评分逻辑，理应零改动）
- `tests/visual/logic_check.py` 前端回归须全绿
- `tests/visual/capture.py` 在深浅两套主题下各截一遍，人工确认无破版
- `tests/visual/theme_preview.py` 作为主题回归基线，改版后重跑比对
- 窄屏（375px）与桌面（1280px）各验一次
- 静态资源版本戳 `?v=50 → ?v=51`，并同步 `app.js:518` 的 `UI_VERSION`
  （后端版本一致性检查会因此提示，属预期）

## 六、不做

- 不改评分权重、判定阈值、数据源（纯呈现层）
- 不引入前端框架/构建步骤（保持"零构建、双击即用"）
- 不新增第三方库（图表用现有 ECharts，动画用 CSS + rAF）
- 不动火烧云/反烧等数据地图的算法与配色语义（`probColor` 高=红=大烧的口径保留）
