# GlowChaser 逐光者 · 火烧云与悬日月预测软件 — 方案设计

> 版本 v1.0 · 2026-09-03 · 目标区域：珠三角（珠海/深圳/广州/中山优先），验证后推广全国
> 理论依据：sunsetbot.top《火烧云预报教程》章节一~四 + sample.pdf（TAKO 珠海晚霞报告，8 维度评估可视化基准）

## 1. 产品定位

面向摄影师的天空摄影可行性预报 Web 应用，输出两类核心预报：

1. **火烧云预报**（朝霞/晚霞）：概率 %、质量分级、开始时刻、持续时间、颜色区间、出现在哪片天空、翻车风险；
2. **悬日月预报**：日/月升落时刻与方位角、低角度悬日月窗口（方位对准 + 高度角合适）、月相照度、结合云况的可见概率。

参考产品：霞AfterglowBot（多模型 consensus、质量/概率双指标、逐时云量分层）+ TAKO 报告（8 维度权重评分、地图+截面可视化）。

## 2. 理论核心（教程推导结论，代码直接采用）

### 2.1 几何模型（章节一 1.2）
- 霞光带宽度（云底高 h 的火烧云可存在区间）：
  - 精确弦长 `W = 2·√(2Rh + h²)` ≈ `2·√(2Rh)`（R=6371km）——教程表 1.3/1.4 采值；
  - 保守下界 `√(2Rh)`（霞光带自日落线向夜侧扫过的宽度）。
- 火烧云三角：霞光带 [x_t−W, x_t] 以日落线速度 v 随晨昏线扫过云层；
  - 观察者头顶云底被照亮持续 `t_overhead = W/v`；
  - 云边界距观察者 d_e（云层在向日侧）时，光需从云边界下方穿过：
    `t_start = max(0, (d_e − h·R/d_e))/v`，`t_end = W/v`；
  - 高度角换算：`z ≈ d·tanθ − d²/(2R)`；θ_边界 = atan(h/d + d/(2R))。
- 日落线速度 v：由太阳几何数值微分 `v = R·|dα/dt|`（约 15~23 km/min，随纬度/季节变化），不查表。
- 等效云底高度（AOD 消光修正，章节四 4.1）：`h_eq = h_cloud − H·ln(AOD/k_th)`，k_th=0.02/km（550nm 消光阈值），H=气溶胶标高（默认 1.5km，区间 0.5~4km 做敏感性输出）。

### 2.2 光谱与消光（章节一 1.3 / 章节二 2.4）
- 鲜艳度：瑞利散射 λ⁻⁴ 主导 → 色彩饱和；气溶胶米散射 → 色彩发白。**要求整条光路洁净，本地洁净不够**。
- AOD(550nm) 视觉对照（教程表 2.3）：<0.1 水晶天 / 0.1~0.2 通透 / 0.2~0.3 较蓝 / 0.3~0.5 普通 / 0.5~0.8 明显影响 / >0.8 污烧。
- 亮度带（教程 FAQ）：550nm 透射 1/几~1/几十 = 亮烧；1/几十~1/几百 = 闷烧；<1/1000 无观赏价值。
- 颜色（章节一 1.3.4）：云底越高颜色区间越全（金→橘红）；光路越远越红；低云因 AOD 近地消光难出好烧。

### 2.3 云属价值（章节二 2.1）
| 云属 | 火烧云价值 | 备注 |
|---|---|---|
| 高层云 As | ★★★★★ 最壮观 | 橘黄→红，2.5km+，厚 |
| 卷层云 Cs | ★★★★★ | 面积大持续久，6km+ |
| 卷云 Ci | ★★★★ | 持续长颜色全，6km+ |
| 高积云 Ac | ★★★★ | 橘黄→橘红，常伴冰晕 |
| 层积云 Sc | ★★ | 需云底>2km 且大气洁净 |
| 积雨云 Cb 云砧/对流柱 | ★★★★（夏季主力） | 需处云砧向日侧 |
| 层云 St / 雨层云 Ns | ✗ | Ns 不贡献天象 |
- 纤维状结构（幡状云）= 云底有效高度下降 = 负面因子；乳状云指示云下干空气。

### 2.4 预报流程（章节四）
沿日落方位取大气截面 → 云底高度 → AOD 等效修正 → 几何判定（光路是否可达）→ 时长/时刻计算 → 云属判别（探空/云量分层）→ 天象附加 → 不确定性评估（云量饱和度、边界距离梯度、边界风速 <15/15-30/>30 m/s、边界-方位夹角 <10° 风险）。

## 4. 评分体系（对齐 sample.pdf 8 维度）

| # | 维度 | 权重 | 打分逻辑（0-100） |
|---|---|---|---|
| ① | 中高层云分布 | 23% | 画布条件：中+高云量落入 30~70% 最佳带（100 分），向外线性衰减；低云 <30% 满分，>60% 重罚（遮挡+消光） |
| ② | 光路城市云况 | 30% | 沿日落方位 8~12 个采样点（至最大霞光距离），距离加权中高云均值画布分 + 低云均值惩罚；核心维度 |
| ③ | 近地降水 | 10% | 本地 + 光路沿线降水概率/量：0% 满分，随概率与量衰减 |
| ④ | 能见度/颗粒物 | 11% | visibility → 通透分（≥20km 满分）；PM2.5 ≤15 满分线性衰减 |
| ⑤ | 云运动趋势 | 3% | 日落时刻 vs 前 3h 云量变化率：稳定/缓慢发展加分，快速恶化减分 |
| ⑥ | 气压变化 | 1% | 3h 气压变化：升压趋向晴好加分 |
| ⑦ | CAMS 霾/气溶胶 | 12% | 本地 AOD（表 2.3 对照）+ 光路 AOD 均值双项：≤0.15 满分；>0.5 重罚 |
| ⑧ | 高层湿层卷云潜力 | 10% | 300-500hPa 相对湿度均值：40~80% 最佳（有卷云水源不过饱和），过干/过湿衰减 |

- **综合概率 = Σ 权重分 × 几何可行性门控**：若光路几何不可达（云边界距离 > 最大霞光距离），总分强制上限 25%。
- **多模式共识**：4 模式各自评分 → 加权均值（EC 权重高）− 模式间标准差惩罚 → 概率%；可信度 = 模式一致度（如"高·两模式高度一致"）。
- **质量分级**（概率旁的"质量"）：由 等效云底高度 + AOD + 中高云比例 推颜色区间（金黄/橘色/橘红/暗红）与亮/闷烧。
- **翻车风险标注**：云量欠饱和、边界风速大、边界-方位夹角小、AOD 垂直分布不确定 → 输出 top 风险提示。

## 5. 悬日月模块

- 太阳：Meeus 算法 → 升/落/中天时刻 + 方位角，蓝调时刻（太阳 −6°~−4°）；
- 月亮：截断 ELP2000（主项 ~0.05°）→ 升/落/中天 + 方位角 + 相位照度；
- **悬日月窗口**：用户给目标方位 θ_t（预设地标方向或自由输入，容差 ±2°）→ 找 |azimuth−θ_t|≤tol 且高度角 ∈ [2°,35°] 的时间窗，输出窗口起止、方位/高度范围、（月亮）照度；
- **可见概率**：窗口时刻云况（低云<30% 通透 / 中高云薄可透 / >70% 挡）+ 能见度 → 悬日月可见概率与建议。

## 9. 风险与边界

- Open-Meteo 免费额度：缓存 + 网格降采样兜底；
- CAMS AOD 0.4° 粗分辨率：光路采样点 ≥8 个取均值；
- 云量三分层（3/8km 界）与云属传统界（2.5/6km）差异：评分按三分层归一处理；
- ECMWF 无能见度：visibility 用 best_match 模式补齐并标注口径；
- 珠三角海岸地形：云海/平流雾场景 v1 不做，留 v2。

- **等比投影（v3 核心）**：横竖同一 px/°，取景框严格 = `aov × 画布比例`；视线内容装不下时
  按最小必要倍率外扩，框外多出来的部分只是参照并**整体压暗**（一眼分清取景范围）。
  实测 `pxPerDegX == pxPerDegY`、框长宽比 = 视场比（均有回归用例断言）
- **天体位置锚定窗口值**：偏移 0 时严格等于窗口表里的 (方位, 高度)——读的就是后端解出来的
  同一个数；拖滑块只叠加**轨迹增量**。旧版偏移 0 用窗口值、偏移 ±1 用轨迹绝对值，两者在
  mock 数据下相差 1.2°（超过画面高度的 1/3）；且方位线性插值跨 0/360 会插出 180° 的假值
  （新增 `pvInterpAz`：先展开成连续序列再插值）
- **云带按视线几何落位**：低/中/高云画在「视线与该层交点」所在的**真实视高度角**上（即天体
  仰角——交点本来就在那个方向），厚度由该层在交点距离处的上下界仰角换算；透明度取该层沿
  视线云量 `occ`，三层连乘恰为后端 `trans`，所以**"云缝里露出的日面"与可见度数字同源**。

- **可见度改用后端值**：`w.vis_prob`（有视线评估时 = `trans×100`）优先，不再前端另算一套；

### v2.27（2026-09-14）— 卫星临近校准：投影/取景/时次三处错位修正 + 10 分钟时间轴
- **起因（用户反馈）**：「预览里的光路好像不在我选的目标点那边」。查下去发现不是"看起来像"，
  而是**三个独立的错位叠加**，且单测全绿（不走网络就碰不到）：
  1. **投影常量是估的**。代码用 `(CX, CY, RAD) = (300.5, 300.5, 280)`；实测（JMA 601px
     全圆盘）水平弦 x∈[12,588] → 圆心 x=300、R=288，垂直方向 y=0 处已是盘内、底部
     y≈575 结束 → 圆心 y≈288。**该常量在珠三角造成约 400km 的地理定位偏差** —— 光路
     采样点被算到了真实位置西南 400km 的云上。交叉验证：把 P-Tree 5km 真实亮温按本投影
     重采样后与 JMA 灰度求相关（冷=亮，应为强负相关），旧常量 r=-0.258 → 实测常量
     r=-0.376 → 内圈最优约 (300,286,292) r=-0.45，三者一致
  2. **JMA 裁剪按观测点固定裁 70px**。在珠三角那相当于 **3700km 宽**的画面，而 620km 的
     光路只占其中约 25px（约 1% 面积）——用户看到的"光路"其实是一根看不清方向的小短棒。
     现改为按"观测点 + 光路点"包围盒取景（pad 用 km 给、按本地 px/km 换算），并补上
     比例尺、指北针（正交投影下北不是正上方，用投影对纬度的导数算）、目标端十字
     （TGT）与方位角、逐点距离标签
  3. **P-Tree 亮温裁剪图的纬度映射错**：把"纬度总跨度"当成"每像素跨度"再乘行数
     （差了一个行数的倍数），整条光路被压到画面顶部；同时上下翻了一次导致**南北镜像**
     （判断"云带在我北边还是南边"会得出相反结论）。现改为北在上、跨度按总跨算计，
     并新增**右侧亮温色标**（不画色标只能靠猜颜色）
- **时次语义修正**：JMA 文件名按槽位命名、每日覆盖，实测有槽位挂着 24 小时前的同名旧图

  现拆开：**卫星时次 = 观测槽位时刻**（`age_min` = 观测龄），另给 `published_min`
  发布龄，两者都进界面。JMA 的有效滞后实测约 25~50 分钟
- **新增 10 分钟时间轴**（交互/完整性）：新端点 `GET /api/sat_frame?lat&lon&azimuth&back`
  逐帧取 JMA 光路判读（1 次 HTTP + 按时次进程内缓存，来回拖同一帧 0 请求；实测 15~19ms）。
  槽位**先探测真实可用性**（存在 + Last-Modified 新鲜）再排序，滑块位置严格对应一帧

### v2.26（2026-09-14）— 悬日月「已过窗口 / 下次对准」· 晚霞受光（地影）判据
- **起因**：两个实测问题。①「查明早的悬日月显示查不到、只有今天日出的、而今天已经过了」——

    定向用例（10km 云 α=−2° 受光 / −4° 变暗；300km 处 α=−4° 仍受光）全部成立

  改为「**受光画布**」（各层云量 × 该层该距离的受光程度），反烧同样只统计仍受光的高云。

  - **诚实说明**：本项目判定时刻落在日落后 1~4 分钟，此几何下绝大多数云仍受光，故常见情况下
    dim2 几乎不变（实测珠海/广州 4 组：画布 130→130、123.9→123.9）；真正咬住的是云边界很远
    （时段中点晚）、深暮光与反烧。返回体同时给出 `canvas_raw`/`canvas_lit` 便于事后对照
  - **未做**：时间分辨率仍是整点 / ±1h 均值。`minutely_15` 实测四模式在珠海均可用、

### v2.24（2026-09-14）— 上游额度韧性：429 分级 / 冷却 / 缓存落盘（被共享 IP 打光额度）
- **起因**：实测 `429 {"reason":"Daily API request limit exceeded.   - **磁盘缓存** `data/om_cache/`：按 key 一文件、临时文件 + `os.replace` 原子写、按 TTL 判定过期、启动时后台清理；磁盘命中**全程不发请求**（重启不失忆，也是额度被打光时仍能出结果的兜底）

- **GFS 同几何复核**：同一套交点几何换 GFS 气压层云量重算（GFS 同时提供 `cloudcover_*hPa` 与 `visibility`，与 ECMWF 合并在同一次请求内，不增加 HTTP 次数），输出 `models`/`model_spread`；分歧 ≥40% 时列入风险。实测 2026-09-13 珠海日落：ECMWF 视线低云 46~82%、GFS 低云 0~5%，可见概率差 79~85%——经与各模式自己的分层云量（`cloud_cover_low/mid/high`）核对，气压层云量口径一致，属真实模式分歧而非口径错误
